# 术语表

> 本文是[英文规范术语表](../glossary.md)的简体中文语义对等译文。公共代码标识符保持英文。若两种语言的表述出现差异，以英文文档定义的公共契约为准。

本术语表定义各概念在系统架构中的边界，并不要求最终用户学习或编辑本体。用户界面应将这些术语转换成“保留、替换、调整、创建、删除、忽略某个来源”等自然操作。

## 设计输入与证据

### `CaseSpec`（案例规格）

某一次设计修订的标准化请求，包括用户意图、参考素材、可信元数据、交互模式、宿主策略和目标输出。`CaseSpec` 是解释和编译的输入，不代表用户已经授权调用外部服务或产生成本。

### `CompilationContext`（编译上下文）

某个编译检查点允许依赖的全部内容所形成的不可变、内容寻址快照。它绑定 `CaseSpec` 的修订版本与哈希、引用的产物哈希、已接受决定、Schema 与规则版本、组件与适配器版本、能力档案版本、宿主策略快照、已声明远程目的地以及适用的调用和成本预算。

每个快照都有一个 `contextHash`。新增或改变任何输入、决定、版本、目的地或预算都会创建新的 `CompilationContext`，不得修改已经获得授权的上下文。编译期远程调用和最终执行授权都绑定相应的 `contextHash`，避免检查完成后、实际使用前请求内容被替换。

### `ChangeIntent`（变更意图）

描述目标结果中的某个本体路径应如何变化或保持稳定的结构化声明。操作包括 `preserve`（保留）、`replace`（替换）、`adjust`（调整）、`create`（创建）和 `remove`（删除）。

`ChangeIntent` 描述目标结果，不负责决定由哪张参考图提供证据。特别是，`remove` 表示目标结果中不得存在某个实体或属性，与禁止继承某条观察证据不同。

### `RequestedScopePlan`（请求范围计划）

针对当前任务，理解器被允许或必须分析的最小本体范围计划，同时包含目标素材、分析目的、排除范围和澄清问题。

它在详细视觉解析之前，根据用户意图、场景策略、素材提示和 `OutputContract` 推导。它限制成本和隐私暴露，并避免因为本体可以表达很多字段就对图片进行穷举式描述。

### `Observation`（观察项）

针对一项参考素材和一个本体路径提出的一条不可变候选判断。它包含值、`Provenance`、可选的 `confidence`、可选的 `EvidenceRegion`、分析器版本信息、警告和内容哈希。

`Observation` 只表示模型、用户标注或可信元数据报告了什么；它不会自动成为已接受事实、硬约束，也不会自动要求继承所观察到的属性。

### `ObservationDecision`（观察项决定）

针对一条 `Observation` 单独保存的接受决定。它记录 `proposed`、`confirmed` 或 `rejected` 状态、获得授权的决定主体、理由、时间，以及该决定适用的观察项内容哈希和上下文版本。

观察项发生变化时会产生新哈希，绑定旧内容的决定随即失效。序列化视图可以在观察项旁投影当前决策状态，但观察项载荷与具有权威性的 `ObservationDecision` 必须保持为两类独立记录。

### `ReferenceObservation`（参考图观察记录）

理解一项参考素材后得到的概念级或适配器级记录，通常包含多条 `Observation`、待裁决事项和警告。因此，一张图片可以同时提供关于人物外观身份、头发、表情、姿势、衣着、饰品、背景、光线和镜头的多个观察项。

`Observation` 是来源裁决阶段使用的标准化单条候选声明；`ReferenceObservation` 可以作为传输包装，但不得把一张图片压缩成唯一角色，也不得静默接受图片中的全部观察项。

### `EvidenceRegion`（证据区域）

表示某条 `Observation` 的图像证据位于何处的可辨识联合类型。首批变体包括：带归一化坐标的 `rectangle`、带归一化点集的 `polygon`，以及包含 `ArtifactHandle` 的 `mask`。矩形与多边形坐标使用各自类型字段定义的坐标空间；蒙版坐标空间由所引用的产物合同定义。每种变体都有明确的 `kind`；使用方不得根据可选字段猜测区域形状。

`EvidenceRegion` 用于解释和复核，并不能证明观察结论正确。缺少证据区域表示没有可用的位置证据，不表示该结论适用于整张图片。

### `Provenance`（溯源信息）

描述一条候选声明、事实、建议或决定来自哪里以及如何形成的机器可读溯源信息。至少要区分用户明确输入、参考图观察、可信元数据、规则推导、优化器建议和声明式默认值，并记录相关来源及版本标识。

`Provenance` 回答“它从哪里来”，与确定程度、重要程度和是否被接受相互独立。

## 意图、证据与已接受事实

### `Intent Interpreter`（意图理解器）

可替换组件，将标准化用户语言和场景上下文转换成 `ChangeIntent`、`RequestedScopePlan`、歧义项以及不支持或不安全的请求。它不分析未经允许的范围，也不创建已接受的本体事实。

### `Reference Interpreter`（参考图理解器）

可替换的手工、固定样例或多模态组件，只分析 `RequestedScopePlan` 允许的素材与本体范围，并使用严格 Schema 和带版本的分析器元数据输出 `Observation`、待裁决事项和警告。

它只观察候选证据，不决定任务应该继承什么，也不得把人物外观身份、商品保真、材质或 Logo 的模型猜测直接提升为事实。

### `SourceBinding`（来源绑定）

目标本体路径与选定观察证据之间的一条候选关系。关系说明证据是否可以用于 `preserve`（保持）、`reproduce`（复现）、`inspire`（启发）或 `exclude`（排除）某项属性；优先级说明该关系的要求强度。

`SourceBinding` 回答“哪些证据可以或不得为这个目标提供来源”；`ChangeIntent` 回答“目标结果应该发生什么变化”。例如，替换原外套可以同时使用操作为 `replace` 的 `ChangeIntent`，以及从另一张图中 `reproduce` 新外套的 `SourceBinding`。

### `BindingDecision`（绑定决定）

一条 `SourceBinding` 的明确接受状态和决策权限记录。它说明绑定处于 `proposed`（待确认）、`confirmed`（已确认）还是 `rejected`（已拒绝），由谁或什么被授权作出决定、决定原因，以及该决定适用的绑定内容哈希和上下文版本。

即使相关观察的置信度很高，待确认绑定也不能自动使用。高影响绑定可能必须由用户、可信元数据或宿主策略确认。

### `Evidence and Source Resolver`（证据与来源裁决器）

确定性组件，组合 `ChangeIntent`、观察项、`ObservationDecision`、可信元数据、之前确认的绑定决定和宿主策略，产出已接受的 `SourceBinding`、`BindingDecision`、稀疏 `OntologyInstance`、澄清问题、冲突、待裁决事项和决策轨迹。

它是候选证据与可进入编译的已接受事实之间的边界，不得通过虚构一个值来掩盖歧义。

### `OntologyInstance`（稀疏本体实例）

稀疏本体实例是与当前任务相关、已被接受并保留来源及来源绑定关系的事实集合。本体词汇可以很广，但 `OntologyInstance` 只包含当前任务所需且有证据支持的事实。

缺失字段保持缺省或明确为未知，系统不得为了“填完整”而补齐本体。

## 场景打包与组合

### `ScenarioPack`（场景包）

带版本、可分发的声明式数据包，通过组合声明式规则贡献项、场景默认值、类型化 `OverridePoint` 记录、`UIMetadata`、`FixtureSuite`、兼容性声明、迁移、文档、许可证和溯源信息，将 VOCE 公共合同组成一个可复用场景体验。

`ScenarioPack` 不是模型提供方适配器、托管应用、账户或商品目录模型、执行计划、远程调用授权或 JavaScript 入口。Core 只读取它的清单，以及按内容寻址、可 JSON 序列化的贡献项。商业虚拟试衣、Cosplay 和商品图是使用相同 Core 公共接口的首发示例包；Core 不会依据它们的场景 ID 进行分支。

### `ScenarioPackManifest`（场景包清单）

`ScenarioPack` 的静态、机器可读声明。它包含稳定的 `packId`、版本、Core 与合同兼容范围、依赖和扩展关系、贡献项 ID、可覆盖点、`UIMetadata`、Fixture、迁移、能力要求、可审计包声明、完整分发清单、许可证、完整性信息和 `PackageProvenance`。

清单描述包的行为与兼容性。安装或读取清单不会启用场景包、执行 ScenarioPack 入口、授权远程调用或授权费用。对于另行注册的 code-backed 插件，它既不是沙箱，也不是安全证明。

### `ScenarioPackTemplate`（场景包模板）

带版本的脚手架，为新的 `ScenarioPack` 创建最小合法目录、清单、示例声明式 `RulePack` 贡献项、支持 locale 的用户界面元数据、可再分发 Fixture、`ScenarioMigrationDeclaration` 结构、文档和离线验证命令。

模板产物只是起点，不能证明最终场景包已经完整、安全、兼容或达到生产就绪状态。

### `RulePack`（规则包）

一种概念性的语义规则模块。在 `ScenarioPack` 内部使用的 v0.1 候选数据合同是 `DeclarativeRulePackContribution`，只有在 Schema 与兼容性 Fixture 发布后才成为兼容性稳定接口；可执行实现使用独立的实验性 `RulePackPlugin` 边界。

一个 `ScenarioPack` 可以组合多个声明式规则贡献项。`RulePack` 与 `ScenarioPack` 是两个不同概念，不能作为同义词使用。

### `DeclarativeRulePackContribution`（声明式规则包贡献项）

带版本、按内容寻址、确定性且无副作用的规则文档，可以贡献约束、解释、降级和复核要求。它不执行网络调用、不读取密钥、不产生费用，也不作出接受或授权决定。

### `RulePackPlugin`（规则包插件）

通过受信任本地插件路径注册的实验性 code-backed 规则扩展，绝不通过 ScenarioPack 贡献数据注册。它在 v0.1 中拥有宿主进程权限，不属于 ScenarioPack 纯数据安全边界。

### `ScenarioPackSelection`（场景包选择）

场景解析的不可变请求输入：恰好一个根 `ScenarioPack`、零个或多个被显式选择的扩展包，以及一个可选、绑定到案例修订的 `HostPolicyOverlay`。只有确定性解析才能加入必需依赖扩展包，而且其轨迹必须披露这些扩展包。

安装不会创建选择；选择也不会启用场景包或授权任何远程或付费步骤。

### `ScenarioPackCatalogSnapshot`（场景包目录快照）

显式注册的本地 ScenarioPack Descriptor、宿主可用性策略、Registry Revision、ScenarioPack 合同版本和 Resolver 版本的不可变快照。它的 `catalogHash` 覆盖按序排列的语义 Descriptor 与 Policy 投影，是解析及最终 Lock 的输入；Acquisition Locator 被排除，后续 Registry 变化不能改变已有 Snapshot。

### `ScenarioComposition`（场景组合）

根据 `ScenarioPackSelection` 解析得到的包与贡献项关系图：一个根 `ScenarioPack`、被显式选择或依赖所需的扩展包、其中的声明式规则及其他贡献项，以及类型化宿主叠加层。两个不相关的根场景包不会被隐式合并。

组合依据已声明关系和兼容规则，不依赖加载顺序或静默的后者覆盖前者（last-wins）行为。

### `ScenarioCompositionLock`（场景组合锁定记录）

`ScenarioComposition` 解析后的不可变记录。它固定精确包版本，清单、包、配置、依赖与贡献项摘要，Catalog、Resolver、Contract 与 Canonicalization 版本，确定性组合顺序，宿主策略叠加层哈希、兼容性结果、`compositionHash` 和 `lockHash`。

锁定记录使组合可以审计和重放。它不会启用场景包或授权执行，包升级或卸载时也不得改写它。

### `EffectiveScenario`（有效场景定义）

根据合法 `ScenarioCompositionLock`，在应用其中已接受的 `HostPolicyOverlay` 和 `HostOverride` 记录后生成的不可变、按内容寻址的语义场景定义。它包含新案例编译可消费的已解析本体词汇、声明式规则、理解范围、提示词段落、复核模板、默认值、能力要求、可审计声明、组合顺序、已应用覆盖 ID 和 `effectiveScenarioHash`。`UIMetadata` 仍是该语义结构之外的展示元数据。

VOCE Core 消费这一公共结构及其哈希，而不是根据内置场景 ID 进行分发。任何已接受的组合或覆盖变化都会生成新的 `EffectiveScenario`，并在适用时使绑定到旧哈希的上下文或授权失效。

### `HostOverride`（宿主覆盖）

绑定到案例修订的 `HostPolicyOverlay` 中，一项不可变、类型化的宿主操作。它只能通过场景包声明的 `OverridePoint` 设置已声明包配置、设置明确允许覆盖的已声明默认值，或改变明确允许覆盖的 `preferred` 贡献项启用状态。

`HostOverride` 不得修改已安装包、重定义词汇、削弱 Core 不变量、静默降低 `hard` 或 `required` 约束、改写已接受证据或决策、绕过授权，或引入未披露的远程目的地。已接受和被拒绝的请求都会在 `PackResolutionReport` 中保留溯源信息。

### `HostPolicyOverlay`（宿主策略叠加层）

不可变容器，将零个或多个类型化 `HostOverride` 记录、权限来源和理由绑定到一个案例修订，并将它们纳入确定性解析哈希。它由宿主持有，不是场景包贡献项。

该叠加层不能削弱宿主策略，也不能创建网络、模型提供方、费用、证据、决策或执行权限。要将其内容用于另一个修订，必须创建新的显式绑定记录。

### `OverridePoint`（可覆盖点）

清单中对宿主可以覆盖的某个位置作出的声明：包配置、已声明默认值，或已声明贡献项的启用状态。它包括稳定 ID、目标类型与路径、可选值 Schema、是否允许停用，以及最高只能影响 `preferred` 重要程度。

任何未声明为 `OverridePoint` 的内容都不能由宿主覆盖。类型化覆盖本身不会授权网络调用或豁免约束。

### `ScenarioPackConflict`（场景包声明冲突）

清单中声明的与另一个包 ID 及版本范围之间的不兼容，并带有稳定原因代码。它是确定性解析的输入，不是加载顺序提示。

### `ScenarioResolutionConflict`（场景解析冲突）

确定性解析因依赖、兼容性、摘要、顺序、贡献项、迁移或类型化宿主覆盖失败而产出的结构化冲突。它记录稳定原因信息、涉及的包版本与内容摘要、受影响路径或贡献项、严重程度和候选解决方案。

阻断型 `ScenarioResolutionConflict` 会阻止启用。它不会通过包加载顺序、静默省略或隐式削弱来解决。

### `PackResolutionReport`（包解析报告）

解析 `ScenarioPackSelection` 及其可选 `HostPolicyOverlay` 得到的确定性结果。它标识已选择包、依赖与组合轨迹、已应用或被拒绝的覆盖、警告、最小可解释 `ScenarioResolutionConflict` 集合、可执行解决方案、最终锁定记录或已阻断状态，以及每项有效贡献的溯源信息。

解析报告是一种解释产物，不是迁移、启用、授权或执行回执。

### `FixtureSuite`（Fixture 测试集）

带版本的案例与预期确定性产物集合，用于离线验证场景包；案例必须是合成、原创、公有领域或得到明确再分发许可的素材。它覆盖成功、冲突、未知、覆盖、依赖、预算、迁移和适用的无人物行为。

标准 Fixture 不使用凭据、私有素材、网络访问或付费模型。它们比较结构化合同、解释、计划、签名和 Mock 回执，不把生成像素当作 Golden Output。

### `UIMetadata`（用户界面元数据）

支持 locale 的展示元数据，包含 `displayName`、`description`、可选 `instructions` 和消息键映射；带严重程度和可解析消息键的稳定披露记录；以及必须提供文本替代、参考素材选择支持键盘操作、信息不能只依赖颜色的无障碍声明。

`UIMetadata` 不具有语义或授权权限。它的 `defaultLocale` 必须存在，必需披露消息键必须能够解析并在启用前得到确认；无障碍声明定义宿主渲染器要求，而不是对宿主应用提供认证。

### `PackActivation`（包启用）

宿主在必需离线门禁和披露通过后，将一个案例修订显式绑定到准确选择、Catalog/Registry Revision、`ScenarioCompositionLock`、`EffectiveScenario` 与解析报告哈希的记录。安装、注册、解析和检查发生在启用之前，但不代表已经启用。

启用不会授予远程调用或执行权限。现有上下文、授权和执行运行继续固定到它们记录的包版本与内容摘要。

### `PackDeactivation`（包停用）

宿主不可变可用性策略记录，在精确 Registry Revision 上阻止某个包或精确版本获得新的 Case-scoped Activation，但不删除本地字节或历史记录。它与 `PackActivation` 分离，不会取消进行中工作，也不会抹除包溯源信息。

卸载前通常需要先停用。反向依赖和正在使用的状态仍然可能阻止卸载。

### `PackUninstallCheck`（包卸载检查）

从精确 Registry Revision 移除本地可用 ScenarioPack 数据前的不可变预检结果。它记录阻断原因、活动 Activation 与可用性策略、Selection、反向依赖、编译会话、执行运行、待处理迁移、重放要求，以及当前是否阻止卸载。检查本身不授予删除数据的权限。

### `PackUninstallReceipt`（包卸载回执）

基于匹配的允许卸载检查进行原子 Registry Removal 的不可变结果。它记录 Registry Revision、已移除本地包字节、Descriptor/Provenance Tombstone Hash、保留的历史记录、变为不可用的重放 Lock Hash 和回执哈希。卸载绝不删除用户资产、历史证据、决策、运行或回执，也绝不替换成另一包版本。

### `ScenarioMigrationDeclaration`（场景迁移声明）

场景包提供、按内容寻址的声明式迁移记录。它标识稳定迁移 ID、源版本范围、目标版本、允许的配置或贡献项 ID 操作，以及内容摘要；它是数据，不是可执行生命周期钩子。

迁移声明不执行网络或模型提供方调用，也绝不改写历史观察项、决策、编译上下文、执行运行、事件或回执。

### `MigrationPlan`（迁移计划）

根据适用 `ScenarioMigrationDeclaration`，为准确的源 `ScenarioCompositionLock` 与目标 `ScenarioPackSelection` 构建的确定性、可预览、无网络计划。它固定源案例修订/可编辑状态哈希，以及目标案例修订、Catalog、Lock、EffectiveScenario 与解析报告哈希，包含有序操作、待裁决项和 `planHash`；破坏性或有歧义的操作必须带可审计确认哈希。

Dry-run 已经解析并固定目标选择、Catalog、锁定记录与 `EffectiveScenario`。应用安全计划时会校验这些 Pin 和源可编辑状态哈希，然后只创建下一可编辑案例修订与 `MigrationReceipt`。缺少必需声明或存在不安全的待裁决项时，候选版本会被阻止启用，而不是猜测转换方法。

### `MigrationReceipt`（迁移回执）

某次 `MigrationPlan` 尝试的不可变记录，包括计划哈希、源与目标锁定记录及有效场景哈希、新案例修订、已应用操作哈希、待裁决项和回执哈希。它不包含密钥或私有产物内容，也不是执行授权。

### `ScenarioPackPublishAudit`（场景包发布审计）

一次普通干净打包审计的不可变结果，包括完整分发、语义包与清单哈希、校验器与模板版本、Fixture 测试集摘要、带安全证据哈希的检查结果，以及 `auditHash`。

通过审计只证明符合 ScenarioPack 合同及已声明离线 Fixture。它不会安装、注册、启用或授权，不会认证安全性、证明模型质量，也不会建立生产就绪结论。

### `PackageProvenance`（包供应链溯源信息）

已发布场景包由作者声明的机器可读供应链来源：发布者，以及可选的源码仓库、修订和源码摘要。宿主拥有的 `PackageAcquisition` 单独记录来源类型、定位符、完整分发摘要和未执行生命周期脚本；`ScenarioPackDescriptor` 则记录计算出的语义包内容摘要。

`PackageProvenance` 支持完整性与信任决策，但不是官方背书、安全证明、权利保证或生产就绪声明。

### `PackageAcquisition`（包获取记录）

由宿主持有的记录，说明 ScenarioPack 字节从何处取得、完整分发归档的摘要，以及未执行包生命周期脚本。它不是作者提供的溯源声明，也不授予信任或启用权限。

## 编译与规划

### `ConstraintIR`（约束中间表示）

与模型提供方无关、可序列化的中间表示，包含已接受目标、软硬约束、冲突、依赖、共享资源、降级偏好、复核要求、解释、规则轨迹和确定性签名。

### `Constraint Graph Compiler`（约束图编译器）

确定性编译器，将已接受事实、`ChangeIntent`、来源绑定、`OutputContract` 和带版本的规则包转换成 `ConstraintIR`。它传播依赖、遮挡、可见性、不兼容关系和资源占用，并在调用模型提供方之前解释阻断冲突或允许的降级。

### `ReferencePlan`（参考图计划）

针对目标模型提供方能力档案，对参考素材进行选取、排序、淘汰和阻断的确定性记录，同时包含依赖关系、数量与字节预算以及每项决定的原因。

### `Reference Budget Optimizer`（参考图预算优化器）

在模型提供方的参考图数量、字节大小、顺序、角色和依赖限制下生成 `ReferencePlan` 的规划器。它要保留必需的主图与细节图依赖和来源隔离，不能静默截断输入，必须解释每次淘汰。

### `OutputContract`（输出契约）

对最终产物的明确目标要求，例如尺寸、宽高比、格式、Alpha 通道、背景行为、字节限制和下游用途。它描述目标结果，而不是假定某一个模型提供方可以直接生成该结果。

### `ProviderCapabilityProfile`（模型提供方能力档案）

带版本的模型提供方能力与限制说明，来源可以是实际验证或正式契约，包括支持的输入、参考图预算、生成或编辑行为、输出格式、Alpha 支持、超时、已知不兼容项和验证证据。

### `PipelinePlan`（执行管线计划）

利用已声明适配器能力满足 `OutputContract` 的有界无环执行计划。它包含 Schema 版本和内容哈希、步骤及适配器版本、依赖关系、最大调用次数、重试、超时、数据目的地、清理义务、成本上限和可行性解释。

### `Capability-aware Pipeline Planner`（能力感知执行流水线规划器）

确定性规划器，将 `OutputContract` 与 `ProviderCapabilityProfile` 以及已注册处理步骤进行匹配。它可以规划素材解析、生成、临时发布、显式注册的通用后处理、画布标准化、结构校验、语义复核和清理。如果在声明的预算内无法满足输出契约，它必须在付费调用之前失败。

### `Provider Adapter`（模型提供方适配器）

有边界的集成组件，将经过验证的计划步骤转换成某个外部或本地模型提供方请求，并将响应标准化。它必须声明能力、数据目的地、可能费用、超时与重试行为和脱敏规则；不得重新理解任务意图、静默删除或重排必需参考图、虚构能力、增加调用或削弱 `OutputContract`。

## 授权与 TOCTOU 防护

### `RemoteCallAuthorization`（远程调用授权）

针对一个远程或可能产生费用的步骤所作的明确、有界授权，不论该步骤发生在编译期间还是已批准的 `PipelinePlan` 内。它绑定当前 `contextHash`、调用目的、适配器与模型版本、允许使用的 `ArtifactHandle` 和范围标识、远程目的地与区域、最大调用次数、重试、字节、耗时和成本、过期时间以及幂等键。

它只授权指定步骤，不能授权另一个步骤或整份计划。图片生成或其他计划执行还必须获得精确的 `ExecutionAuthorization`；任何被绑定值发生变化都需要重新授权。

### `ExecutionAuthorization`（执行授权）

针对一份精确编译结果创建并调度一次 `ExecutionRun` 的明确授权。它绑定 `contextHash`、`PipelinePlan` 的版本和哈希、选定 `PromptCandidateIR` 或确定性 `PromptIR` 的哈希、能力与适配器版本、远程目的地、输出要求、调用/重试/时间预算、成本上限、过期时间和授权主体。

每次远程调度前，运行时必须重新计算并比对所有被绑定的哈希与快照。任何不一致都会让授权过期并阻止调用。授权不能跨新修订版本、目的地、模型提供方版本、提示词候选、计划或增加后的预算复用。这种“调度时再次检查”是项目防范检查时与使用时不一致（time-of-check/time-of-use，TOCTOU）的主要措施。

## 提示词编译与保护

### `PromptIR`（提示词中间表示）

由已接受事实和约束确定性编译得到、与模型提供方无关的结构化提示词表示。各部分将文本与请求参数关联回约束和来源标识，同时包含禁止项、已规划参考图、`OutputContract` 和确定性签名。

`PromptIR` 不是可直接发送给模型提供方的自然语言提示词，也不会被后续优化或模型提供方改写覆盖。

### `PromptCandidateIR`（候选提示词中间表示）

从 `PromptIR` 派生、面向特定模型提供方的结构化不可变候选。它包含候选提示词区段、请求参数、参考图映射、关联到来源与约束标识的明确变换集、带溯源信息的新增内容、覆盖声明、警告、目标适配器及版本和内容哈希。

它只是等待门禁检查和授权的候选项，既不是语义等价证明，也不是执行许可。确定性编译器可以产出一份基线 `PromptCandidateIR`；可选优化器可以产出更多候选项。

### `Prompt Optimizer`（提示词优化器）

可选的离线或模型驱动组件，通过改写、重排、删除冗余、将意图移入参数，或添加当前模式允许的建议，为目标模型提供方适配 `PromptIR`。它输出一份或多份 `PromptCandidateIR`，其中包含明确的变更集、覆盖声明、带溯源信息的新增内容和警告。

优化器可以改善表达，但不得静默修改人物外观身份策略、商品保真、已确认来源绑定、硬性姿势或资源决定以及 `OutputContract`。

### `Prompt Guard`（提示词约束门禁）

独立的确定性检查，将 `PromptCandidateIR` 与 `PromptIR`、已接受绑定、请求参数和硬约束进行比较。它可以证明 Schema 有效、标识符和结构化字段得到覆盖、参数一致，以及声明的变换是否属于允许清单；当出现可确定判断的结构化遗漏、矛盾、绑定变化、禁止的结构化新增，或把建议升级成用户事实时阻止执行。

即使全部必需标识符都存在，提示词约束门禁也无法确定性证明任意自然语言保持了原有语义。如果候选项使用了受控确定性模板之外的自由文本改写，策略必须要求人工或概率性语义复核、拒绝该候选项，或者回退到确定性提示词候选。概率性复核只能辅助决定，并不是证明。提示词约束门禁只证明结构覆盖和被允许的结构化变换，也不宣称生成模型一定会遵循提示词。

### `providerRevisedPrompt`（模型提供方改写提示词）

生成模型提供方在支持时返回的提示词改写结果。它作为独立的模型提供方产物留存，用于审计和比较，绝不覆盖 `PromptIR` 或本项目自己的优化结果。

## 校验与复核

### `Structural Validation`（结构校验）

对产物及其执行合同进行确定性或直接可测量的检查，例如文件签名、MIME 类型、尺寸、Alpha 通道、字节大小、预期输出数量、哈希和必需回执。通过结构校验不能证明视觉或语义保真。

### `Semantic Review`（语义复核）

由概率模型或人工评估含义与视觉保真，例如人物外观身份连续性、服装或商品细节、遮挡、姿势合理性、材质表现或艺术可接受性。结论保留复核者和版本来源，也可能产生 `needs_review`；不得静默提升为客观事实。

## 生命周期、产物与证据

### `CompilationSession`（编译会话）

针对一个 `CaseSpec` 修订版本，在执行前完成意图理解、证据裁决、编译和规划的生命周期。它通过不可变的 `CompilationContext` 快照逐步推进。任何远程理解器或优化器步骤都需要独立的 `RemoteCallAuthorization`，并产生步骤事件和回执。会话可以进入 `ready` 或 `blocked`；`ready` 只表示已经存在可行且有界的计划，不授予 `ExecutionAuthorization`。

### `ExecutionRun`（执行运行）

在一份精确 `ExecutionAuthorization` 下执行已确认 `PipelinePlan` 的一次尝试。它拥有独立状态、被绑定哈希、预算、适配器快照、回执、输出和父修订版本。重试或实时重新执行需要重新授权并创建新的 `ExecutionRun`，不能伪装成具有“恰好一次”语义的原执行延续。

### `ArtifactHandle`（产物句柄）

由宿主持有、采用内容寻址方式引用输入、中间产物、输出、蒙版或报告的不透明句柄。它只暴露内容哈希、媒体类型、字节大小、逻辑角色、解析器标识、可用性状态、保留类别或过期时间和脱敏策略等安全元数据，不暴露图片字节、Base64 数据、凭据或会过期的 URL。

宿主负责存储、访问控制、保留和删除。每次使用时都要检查可用性。如果产物已过期或被删除，句柄记录 `expired` 或 `deleted`，产物重放返回 `ARTIFACT_UNAVAILABLE`；不得静默重新下载、重新生成或发起付费调用。

### `StepEvent`（步骤事件）

针对一项编译期远程步骤或一个 `ExecutionRun` 步骤的不可变追加式事件。它记录唯一事件标识和关联标识、单调递增序号、步骤和状态变化、时间、绑定的上下文/计划哈希、授权标识、安全的输入/输出摘要，以及适用时的对账元数据。

修正历史必须追加新事件，绝不能重写旧事件。物化状态与回执都是按序事件流的投影视图。

### `StepReceipt`（步骤回执）

一项远程步骤的脱敏证据投影。它既可以关联 `CompilationSession` 中的编译期远程步骤，也可以关联 `ExecutionRun` 中的步骤，并引用生成它的追加式 `StepEvent` 序列。它包含安全标识、被绑定哈希与授权、输入与输出哈希摘要、适配器及版本、时间、可选的模型提供方请求与成本证据、失败代码和清理状态。不得包含密钥、图片字节、Base64 载荷、生物特征描述或会过期的素材 URL。

`submission_unknown` 表示远程请求可能已经被接受或计费，但系统没有收到可靠确认。获得授权的人员或宿主进程可以通过追加模型提供方证据和对账 `StepEvent` 进行人工裁决。运行时绝不能从 `submission_unknown` 自动重提、重试或创建替代的付费调用；主动发起新调用必须获得新授权并使用新的运行或步骤标识。

## 相互独立的判断维度

### `confidence`（置信度）

对一条 `Observation` 是否正确的认知不确定性，通常由理解器输出数值或校准等级。高 `confidence` 不代表用户高度重视，也不代表系统获得了接受该候选结论的授权。

### `importance`（重要程度）

目标结果对某项意图、事实、绑定或约束的要求强度。各值具有明确的执行语义：

- `hard`：只要未满足、存在矛盾或仍待裁决，编译就会被阻断，禁止执行；
- `required`：不得自动降级；只有记录一项明确、可追踪的 waiver（豁免），或者创建改变其重要程度的新案例修订版本，才可以在未满足它的情况下继续执行；
- `preferred`：声明式确定性规则可以自动降级，但降级及原因必须进入轨迹。

高 `importance` 不能证明支撑它的证据正确。waiver 记录的是获得授权的例外，不会重写证据，也不能伪装成要求已经满足。

### `decisionStatus`（决策状态）

表示获得授权的决策是否让候选项处于 `proposed`、`confirmed` 或 `rejected`。确认是一项接受决定，不是置信度分数。具体契约可能使用字段名 `status`；文档在区分这一判断维度时使用 `decisionStatus`。

这三个维度相互独立：高置信度观察可能被拒绝或与任务无关；硬性要求也可能依赖不确定证据，因此仍需澄清。

## 缺失与待裁决信息

### `unknown`（未知）

系统需要或正在跟踪某个值，但没有足够证据断言该值。`unknown` 是开放世界模型中的合法状态，不能用虚构的默认值代替。

### `unspecified`（未指定）

用户、宿主策略或合同没有要求某个值，当前任务也不需要它。`unspecified` 字段通常从稀疏 `OntologyInstance` 中省略，它不是解析失败。

### `unresolved`（待裁决）

系统已经识别出一项会影响结果的问题、歧义、冲突或证据缺口，在某项操作继续之前仍需作出决定或补充证据。待裁决事项应记录原因、影响和可选解决路径。

简而言之：`unknown` 表示“需要但不知道”，`unspecified` 表示“没有要求或当前不需要”，`unresolved` 表示“存在一项已知但尚未关闭的决定或冲突”。

## 重放与比较

### `replay`（重放）

这是包含三种不同语义的总称：

1. **Plan replay（计划重放）**——使用相同 Schema、规则、适配器和能力版本重新编译同一组已确认输入。确定性的 IR、计划和签名应保持一致，不需要再次付费生成。
2. **Artifact replay（产物重放）**——利用仍然可用的 `ArtifactHandle` 和回执重新运行下游处理、评测或报告，不重新提交原模型调用。如果任何必需产物已经过期或被删除，重放返回 `unavailable`，不得静默重新生成。
3. **Live rerun（实时重跑）**——以历史案例或计划为输入，向外部模型提供方提交一次新调用。它需要有效的当前授权，会创建新的 `ExecutionRun`，可能产生费用，也不承诺像素级相同。

文档和 API 必须明确指出采用哪一种重放模式。没有限定的“可复现生成”承诺不得暗示实时生成模型提供方能返回像素级相同的结果。
