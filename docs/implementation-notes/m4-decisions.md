# M4 implementation notes

- M4 adds versioned ConstraintIR, ReferencePlan, ProviderCapabilityProfile, PipelinePlan, authorization, explain, and semantic-diff contracts without changing the M3 evidence resolver. M3 observations, bindings, decisions, and sparse facts remain separate inputs and are verified before compilation.
- All M4 hash projections exclude their own hash and volatile authorization time fields. Arrays are normalized by stable code-unit ordering, and public results are deep-copied before return. A supplied stale hash is rejected; the runtime never repairs it and continues.
- `ConstraintGraphCompiler` consumes only accepted M3 facts and declarative `EffectiveScenario.rulePacks`. The reusable mask/identity, sleeve/bracelet, and hand/prop fixtures are generic rule data; Core contains no scenario-name branch. Hard conflicts block, required conflicts need a scoped waiver for the same case revision/context, and preferred conflicts produce a degradation plus a rule trace.
- Reference budgeting groups candidates by content hash so one asset can cover multiple scopes without being charged multiple times. Required dependency components are retained together; preferred components may be omitted with a reason. Unknown byte lengths never count as known bytes under a finite byte budget.
- The planner uses capability/profile and registered step data only. The offline mock profiles cover standard opaque image output, opaque JPEG plus format normalization, and limited reference budgets. Temporary assets are represented by finally cleanup and compensation obligations for failure, cancellation, uncertain submission, and worker restart; no provider call is executed.
- RemoteCallAuthorization and ExecutionAuthorization are records plus pure dispatch-preflight checks. A ready CaseSpec, ConstraintIR, ReferencePlan, or PipelinePlan is not authorization. Any bound hash, destination, adapter/profile digest, or budget change returns a stable stale/not-authorized result.
- M5 PromptIR, PromptCandidateIR, Prompt Guard, ExecutionRun, StepEvent, StepReceipt, worker execution, real adapters, HTTP transport, and CLI UI remain deferred.
