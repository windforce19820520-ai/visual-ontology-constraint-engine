# M3 implementation notes

- M3 keeps the M2 `ScenarioPackRegistry` and `EffectiveScenario` runtime unchanged. The evidence resolver consumes only the declarative `interpretationScopes` contribution when an `EffectiveScenario` is supplied; it contains no package import, scenario-ID comparison, or first-party scenario branch.
- The public M3 records use the `voce.*\/v1alpha1` schema identifiers added under `packages/contracts/schemas`. `JsonValue` is the closed JSON value type for extensible values; stable records do not use `unknown` output fields.
- `Observation`, `SourceBinding`, `ObservationDecision`, and `BindingDecision` are separate records. Content and decision hashes are computed from canonical semantic projections that omit their own hash field. `FIXED_DECISION_TIME` is used only for deterministic resolver proposals and helper defaults; callers still supply the authoritative decision time for user decisions.
- `ManualReferenceInterpreter` and `FixtureReferenceInterpreter` emit only observations, unresolved items, warnings, and analyzer metadata. Fixture `ref-01` deliberately emits independent identity, hair, expression, pose, wardrobe, background, and camera observations when those paths are allowed by `RequestedScopePlan`.
- `EvidenceAndSourceResolver` performs two explicit phases in one deterministic entrypoint: it proposes bindings and `proposed` binding decisions from currently confirmed observations, then admits facts only from exact current confirmed observation and binding decisions. Rejected, proposed, stale, hash-mismatched, context-mismatched, and out-of-scope records remain traceable and cannot contribute facts.
- Every interpreter/resolver call validates the supplied `RequestedScopePlan` schema version, case identity, revision, and original `planHash` before applying deterministic internal ordering. Invalid plans return `status: 'blocked'`; the runtime never repairs a caller signature and continues.
- Scope authorization is directional: a requested or effective scope authorizes its exact path and descendants only. M3 source binding proposals and confirmed binding admission require exact target/observation paths because no field-projection contract exists yet; parent/child projection is deferred.
- `OntologyFact.acceptedByIds` is the structured acceptance reference for every fact source. For source evidence, `acceptedByDecisionIds` contains the exact confirmed `BindingDecision.decisionId` values and `sourceBindingIds` remains the relationship audit trail; explicit intents and trusted metadata use their own IDs with an empty decision-ID array. Same-value sources merge sorted arrays rather than delimiter-joining IDs.
- Duplicate IDs with different semantic content, and contradictory confirmed/rejected decisions for one subject/content/context, produce stable conflict/unresolved traces and are excluded from fact admission. Exact semantic duplicate records may be deduplicated.
- `unknownPaths`, `unspecifiedPaths`, and `UnresolvedItem` are retained separately. Unequal confirmed values for one target path produce a blocking conflict and question; resolver order, confidence, priority, or last-wins does not select a source.
- The M3 surface intentionally stops before constraint compilation, reference budgeting, provider capability planning, Prompt IR, generation, postprocessing, remote authorization, and paid adapters. Those are M4/M5 work.
